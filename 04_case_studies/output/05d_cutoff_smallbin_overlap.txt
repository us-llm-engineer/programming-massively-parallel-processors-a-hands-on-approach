==================== CUTOFF SUMMATION v4: SMALLBIN-OVERLAP (NVIDIA GeForce GTX 1650 Ti) ====================
[book] the CPU processes the overflow atoms of subvolume i while the GPU executes the next kernel launch.
Compute phase only (no binning/upload). Minimum of 5 runs after a warm-up (robust to interference). 'ideal' = max(GPU alone, CPU alone).
'hidden' = (serial - overlap) / min(GPU alone, CPU alone): 100 % = the shorter piece is completely hidden; n/a when the
shorter piece is under 1 ms. Values well outside 0-100 % are measurement noise (see the note on GPU clocks below).

How to read:
  * Overlap can never beat 'ideal'. If CPU alone >> GPU alone, overlap hides only the GPU time; the CPU pass sets the total.
  * The book's setting has a fast CPU overflow pass (SSE) and few overflow atoms, so the GPU dominates and the CPU pass is
    fully hidden. This CPU code is scalar, so at 4 A the CPU dominates instead; the edge sweep finds where they balance.
  * One slab = no overlap possible (the CPU pass has to wait for the whole launch); more slabs let the CPU start earlier.
  * The timeline of section 3 (8 slabs) is in stats/05d_overlap_gantt.csv.
  * Clock effect: while the CPU works the GPU idles and drops to a low clock (the notes above show 360-435 MHz), so the
    next short kernel starts slow. Each timing group is primed with ~150 ms of GPU work and the minimum of 5 runs is
    kept, but the overlap pipeline itself keeps re-entering that idle state; treat single-digit-ms differences with care.
