'x vs full' = time relative to the first row (max blocks/SM). 2.00x means twice as slow.
Small steps (a few %) are within run-to-run noise; an earlier run showed one 13% outlier.

How to read:
  RAND : random 64 MB gathers are limited by DRAM random-access throughput; even a few warps
         keep the memory system busy, so residency barely matters (no exposed-latency effect).
  SEQ  : coalesced dependent loads are cheap for DRAM but each step waits a full memory latency,
         so time tracks how many warps are resident to cover that wait (the book's claim).
  FMA1 : a dependent FMA chain needs a few warps per scheduler; it only degrades at the lowest
         occupancy rows.
  FMA4 : four independent chains give each thread its own parallelism (ILP), so it tolerates
         low occupancy better. Occupancy is a means to hide latency, not the goal itself.
